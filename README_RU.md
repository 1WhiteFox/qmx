# qmx

[English version](README.md)

qmx (Quantized Model eXchange) — автономный движок инференса квантованных языковых моделей на чистом C99 без внешних зависимостей, встраиваемый SDK и собственный бинарный формат (.qmx).

Проект является идейным продолжением Tunguzka-LLM: из ретро-движка под процессоры Socket 7 он вырос в единую кодовую базу на C99, которая покрывает модели от ~15 тысяч параметров на микроконтроллерах до 4 миллиардов параметров (Qwen3-4B, Phi-3-mini, Gemma-2/3, SmolLM2) на современных x86 и ARM.

## Что делает и зачем

Обычно движки для LLM делятся на крупные фреймворки под современные ПК/серверы и узкие демо-скрипты. qmx — попытка сделать одно компактное ядро на C99 без сторонних библиотек, которое реально работает на обоих краях:

- Бинарный формат (.qmx v1.1): хранит квантованные веса в блочной раскладке 16x32, встроенный BPE-токенизатор и компактный байткод виртуальной машины слоя (Layer Recipe VM).
- Три режима памяти: RAM/mmap для максимальной скорости на ПК, Zero-Copy XIP напрямую из Flash/ROM с внешней статической ареной (0 malloc и 0 stdio для MCU), а также адаптивный стриминг через интерфейс QmxReader для запуска гигабайтных моделей в жёстком лимите ОЗУ.
- 23 бэкенда ISA: Scalar C99, Pentium P54C/MMX, AMD 3DNow!, линейка SSE до AVX-512 VNNI, ARM NEON / NEON-DotProd, ARM-DSP, MCU32 и Cortex-M0..M55.
- Встраиваемый SDK: собирается как статическая библиотека libqmx.a или пара файлов dist/qmx.h + dist/qmx.c; поверх пошагового API qmx_step() собраны консольный клиент qmx и ретро-терминал qmx-term (80x25).
- Упаковщик на чистом NumPy: tools/qmx_pack.py конвертирует HuggingFace SafeTensors (BF16/F16/F32) и чекпоинты llama2.c напрямую в .qmx без PyTorch.

## Кратко об эффективности

По локальным замерам на AMD Ryzen 7 H 255 (Windows x64, FP16 KV-кэш) движок работает во всём заявленном диапазоне:

- Микромодель (~15.5K параметров, MCU XIP без malloc): помещается в ~10.6 КБ Flash и ~6.8 КБ SRAM.
- Компактные модели (260K – 0.5B): от ~188 tok/s на Qwen2.5-0.5B до 40K+ tok/s на TinyStories-260K.
- Модели 4B (Qwen3-4B, Phi-3-mini): ~22–26 tok/s на декоде в RAM-режиме — движок упирается в пропускную способность ОЗУ и слегка обходит AVX2-сборку llama.cpp на декоде (оставаясь медленнее на префилле). В режиме стриминга 4B-модели запускаются в жёстком бюджете 256 МБ ОЗУ.

Подробные таблицы бенчмарков, точные параметры стенда и оговорки по методологии будут вынесены в отдельный файл.

## Быстрый старт

Сборка CLI, TUI и статической библиотеки:

```bash
make host
make test
make amalgamate
```

Упаковка модели:

```bash
# Быстрый тест на TinyStories-260K
python3 tools/qmx_forge.py --fetch stories260k -q q4_r32 -m stories260k.qmx

# Или конвертация модели из HuggingFace (локальная папка или repo ID)
python3 tools/qmx_pack.py --hf Qwen/Qwen3-4B -o qwen3_4b.qmx -q q4_r32 --lm-head-quant q4_r32
```

Запуск:

```bash
# Консоль
./qmx -m stories260k.qmx -p "Once upon a time" -n 64

# Стриминг в бюджете 256 МБ ОЗУ
./qmx -m qwen3_4b.qmx -p "Привет" -n 64 -j 8 --kv16 --stream --max-ram 256

# Терминал 80x25
./qmx-term -m stories260k.qmx
```

Примеры встраивания в свой C-код — в examples/minimal_step.c и tests/test_xip_15k.c.

## Дисклеймер и использование ИИ

Я специалист из непрофильной сферы и мой профиль высшего образования - Бизнес-Информатика. Я всегда горел железом и этот проект - исключительно моё хобби в свободное время. Код предоставляется «как есть» (AS-IS), без гарантий и обязательств по поддержке.

Использование ИИ: общая идея (продолжение Tunguzka-LLM), архитектура рантайма, формат .qmx и подходы к стримингу/XIP придуманы мной, но большую часть кода на C99, SIMD/ассемблере и Python написал ИИ под моим контролем и тестированием.
